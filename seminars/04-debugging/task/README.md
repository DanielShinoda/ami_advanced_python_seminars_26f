# Задача — найти NaN в пайплайне

`nan_hunt.py` собирает показания датчиков и прогоняет их через `minipipe`.
Несколько показаний отравлены `NaN`, и результат выходит `nan`.

Какие именно строки отравлены — выбирается заново на каждый запуск.
Из исходников не угадать.

## Что сделать

Добиться, чтобы **`index` и `sensor` всех отравленных показаний** попали
в stdout pdb-сессии. Писать только в `commands.pdb`, скрипт не трогать.

```bash
make check-hunt
```

Верификатор прогоняет pdb четыре раза, каждый раз с другими отравленными
строками.

## Как запускается

```bash
cd seminars/04-debugging/task
python -m pdb -c continue nan_hunt.py < commands.pdb
```

`-c continue` выполняет `continue` сразу после старта: скрипт бежит до
необработанного исключения, дальше pdb читает команды из файла.

## С чего начать

Запусти как есть и посмотри, где окажешься. Скрипт падает на проверке
результата — а к этому моменту матрица давно собрана, и виновных строк в
том кадре нет.

Значит одного post-mortem мало. Техники разбирали на семинаре:

- `demo/01_postmortem` — куда попадаешь после падения и что видно в
  соседних кадрах
- `demo/02_conditional` — как найти нужный элемент среди тысяч
- `demo/03_commands_restart` — как собрать данные о **всех** битых
  записях, а не только о первой

## Правила игры

Значения надо **читать из работающего процесса**. Верификатор отдельным
пунктом проверяет, что `commands.pdb` не читает файл с ответом, не лазит
в переменные окружения и не вызывает внутренности скрипта напрямую.

## Сдача

Вывод `make check-hunt`: все пункты зелёные.
