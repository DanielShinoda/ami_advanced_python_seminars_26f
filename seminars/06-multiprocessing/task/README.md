# Задача — общий счётчик между процессами

`shared_counter.py`: `count_parallel(workers, times)` поднимает `workers`
процессов, каждый увеличивает **один общий** счётчик ровно на `times`,
и возвращает итог. Итог обязан быть ровно `workers * times` — ни один
инкремент не теряется.

Два TODO: атомарный инкремент в `_bump` и сборка/разборка процессов
в `count_parallel`.

```bash
make check-counter
```

Домашка по multiprocessing держится на **нулевом shared state**
(immutable chunks, мердж в родителе). Здесь намеренно наоборот:
минимальный общий примитив — чтобы почувствовать, почему в домашке
от shared state отказались.

## Посмотреть глазами

```bash
uv run pytest seminars/06-multiprocessing/task -q
```

## Правила игры

- Контекст — `CTX` из модуля (fork). Shared-память разделяется через
  наследование; под spawn эти объекты не пиклятся.
- Каждое увеличение счётчика — под `lock`. Версия без lock обязана
  проиграть: проверка гоняет сотни тысяч инкрементов и сравнивает итог.
- «Посчитать в каждом процессе отдельно и сложить в родителе» —
  обход, а не решение: `_bump` должен работать с общим counter.
